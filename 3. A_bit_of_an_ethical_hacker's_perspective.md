# 🔑 A bit of an ethical hacker's perspective

Things are getting interesting here. Having a machine you control (server machine) and an attacker's machine (client machine) on the same local network is a classic setup in a cybersecurity lab.
From an ethical hacker's (or attacker's) perspective, gaining SSH access to the server machine is just the entry point. From there, there's a lot to do.
Here's what an attacker or pentester would try to do next:

---

### **1. Privilege Escalation:**
If the SSH account you logged in with is not root (for example, you are a regular user), your main goal is to become the ultimate administrator of the system.


### **2. Internal Reconnaissance (Post-Exploitation):**
Once inside, the attacker wants to map the machine to find out where he is and what valuable information he can contains.

### **3. Persistence (Ensuring re-entry):**
An attacker does not want to lose access if the user restarts the machine or changes their password.

## **4. Lateral Movement and Pivoting:**
If the server machine has access to another network or service that the attacker/hacker cannot reach directly, you can use SSH as a tunnel or proxy.

## **5. Data Exfiltration:**
The last goal of many cyberattacks is to steal sensitive information without raising suspicion.
